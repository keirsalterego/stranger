# stranger

A model suggests a package. You paste the name into `package.json`. The name is
not real — nobody has ever published it — and the first person to notice
registers it and ships whatever they like to everyone who runs `npm install`.

`stranger` reads a lockfile and tells you which names in it look invented. It
does not install anything, does not resolve anything, and never opens a socket.

```console
$ ./target/release/stranger scan fixtures/poisoned.package-lock.json

  poisoned.package-lock.json 757 packages   (35 direct · 722 transitive)

  ⚠  HALLUCINATION RISK     3
     chalck@5.3.0             not in corpus · d=1 from "chalk" · root-only, no parent
     expres@4.18.2            not in corpus · d=1 from "express" · root-only, no parent
     lodahs@4.17.21           not in corpus · d=1 from "lodash" · root-only, no parent

  risk 75/100    54ms    third-party deps used to compute this: 0
```

Three planted names, three findings, no false positives. The other five npm
fixtures hold 3,168 real packages between them and produce nothing at all.

## The empty manifest

The last field of that output is checkable. `Cargo.toml` has three dependency
tables and all three are empty:

```toml
[dependencies]

[dev-dependencies]

[build-dependencies]
```

So the lockfile of a lockfile auditor is one package long:

```toml
# This file is automatically @generated by Cargo.
# It is not intended for manual editing.
version = 4

[[package]]
name = "stranger"
version = "0.1.0"
```

That is the whole dependency graph. No `serde`, no `clap`, no `strsim`. The
JSON reader, the argument parser, the edit distance and the report writer are
in `src/`, and the test harness is the one Rust ships with, so there is no
dev-dependency escape hatch in use either. `#![forbid(unsafe_code)]` sits at the
top of both `src/lib.rs` and `src/main.rs`.

Rust's standard library has no TLS and no HTTP client. A binary with no
dependencies therefore cannot make a network request — the guarantee comes from
the empty manifest, not from anyone's restraint.

## Reading files other tools produced

The hackathon rules forbid shelling out to installed tooling. Their FAQ rules
this design in explicitly:

> Parsing files those tools already produced is fine, because nothing
> third-party ends up in your artifact.

Two conditions attach. It has to be disclosed, and it has to degrade when the
file is not there. Both hold. The corpus of known-real names and the fixture
lockfiles are written up in [corpus/PROVENANCE.md](https://github.com/keirsalterego/stranger/blob/main/corpus/PROVENANCE.md)
and [fixtures/README.md](https://github.com/keirsalterego/stranger/blob/main/fixtures/README.md), and pointing `stranger` at a
directory with no lockfile prints what it looked for and exits 0:

```console
$ ./target/release/stranger scan /tmp/empty

  no lockfile in /tmp/empty
  looked for: package-lock.json

$ echo $?
0
```

## What it reads today

One format: `package-lock.json`, lockfileVersion 2 and 3. One rule: the
[co-occurrence rule](detection/rule.md) that separates a hallucinated name from
a legitimate sibling. The rest of this book is what those two things do, what
they measure, and where they are wrong.

Start here:

```console
$ make && ./target/release/stranger scan fixtures/poisoned.package-lock.json
```
